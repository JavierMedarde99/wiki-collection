# Servicios

## Servicios de Colección

### BookService

Implementa `BookUseCase`. Gestiona CRUD de libros.

```java
public interface BookUseCase {
    Page<Book> search(BookSearchCriteria criteria, Pageable pageable);
    Book findById(String id);
    Book save(Book book, String ownerId);
    Book update(String id, Book updates, String ownerId);
    void delete(String id, String ownerId);
}
```

**Responsabilidades:**
- Búsqueda con criterios (nombre, autor, tipo, estado, owner scope)
- CRUD completo de libros con ownership
- Delegar persistencia al repositorio
- Filtra campos privados (notas, valoración) si el visiter no es el dueño

### BookSearchService

Implementa `BookSearchUseCase`. Busca libros en Google Books API.

```java
public interface BookSearchUseCase {
    List<BookSearchResult> search(String query);
}
```

**Responsabilidades:**
- Validar query no vacío
- Delegar a `ExternalBookCatalogClient`
- Manejo de errores: propaga excepciones del cliente externo
- Cacheable con Caffeine (`bookSearch`)

### GameSearchService

Implementa `GameSearchUseCase`. Busca juegos con fallback RAWG → FreeToGame.

```java
public interface GameSearchUseCase {
    List<GameSearchResult> search(String query);
}
```

**Implementación:**
1. Intenta primero RAWG (búsqueda por nombre nativa)
2. Si RAWG devuelve lista vacía, usa FreeToGame como fallback
3. No cachea resultados (caché se maneja en el cliente RAWG/FreeToGame)

## Servicios de Autenticación y Perfil (Fase 8)

### AuthService

Implementa la lógica de autenticación: registro, login, refresh de token.

```java
public AuthResponse register(RegisterRequest request);
public AuthResponse login(LoginRequest request);
public AuthResponse refreshToken(String refreshToken);
```

**Responsabilidades:**
- Validar que username/email no existan ya (lanza UserAlreadyExistsException / EmailAlreadyExistsException)
- Codificar password con BCrypt
- Generar accessToken (15 min) + refreshToken (7 días) con JwtService
- Devolver AuthResponse con tokens + UserResponse

### JwtService

Gestiona la generación y validación de tokens JWT.

```java
public String generateAccessToken(User user);
public String generateRefreshToken(User user);
public String extractUserId(String token);
public boolean isTokenValid(String token);
```

**Configuración:** `app.jwt.secret`, `app.jwt.access-token-expiration` (900000ms = 15 min), `app.jwt.refresh-token-expiration` (604800000ms = 7 días).

### UserDetailsServiceImpl

Implementa Spring Security `UserDetailsService` para cargar usuarios por userId (no por username).

```java
public UserDetails loadUserByUsername(String userId);
```

**Nota:** El subject del JWT es el userId, no el username.

## Servicios de Infraestructura

### OwnerResolver

Resuelve el ownerId del usuario autenticado desde el SecurityContext.

```java
public String resolveOwnerId(); // null si no hay usuario autenticado
```

### OwnerScopeResolver

Resuelve el scope de visibilidad a partir del parámetro `owner` del request.

```java
public enum OwnerScope { MINE, OTHER, ALL }
public OwnerScope resolveScope(String ownerParam); // null → ALL
```

### OwnershipValidator

Valida que el usuario autenticado pueda operar sobre un recurso.

```java
public void validateOwnership(String resourceOwnerId, String currentUserId, String resourceType);
```

**Lanza ForbiddenException** si:
- Hay usuario autenticado pero no es el dueño del recurso
- Se intenta modificar un recurso de otro usuario sin ser admin

## Utilidades y Validators

### DeckValidator

Valida el estado de un mazo Commander según las reglas del formato.

```java
public DeckStatus evaluate(Deck deck);
public List<String> validate(Deck deck);
```

**Reglas:**
- DRAFT: Mazo en construcción (< 100 cartas, sin comandante, colores inconsistentes, etc.)
- COMPLETE: Mazo válido (100 cartas exactas, comandante válido, colores correctos, comandante en mazo)
- INVALID: Mazo que viola reglas Commander (más de 100 cartas, comandante fuera de color, etc.)

**Reglas implementadas:**
1. La cantidad total de cartas debe ser exactamente 100 (excepto comandante)
2. El comandante debe estar presente en el mazo
3. Todos los colores de las cartas deben estar dentro de la identidad de color del comandante
4. El comandante debe ser una carta legal de Commander (no revocada/baneada básica)

### DateRangeValidator

Valida que las fechas de inicio/fin sean coherentes.

**Reglas:**
- Fechas no pueden ser futuras
- Fecha de fin no puede ser anterior a fecha de inicio

### PagedResults

Utilidad package-private para convertir `List<T>` en `Page<T>` paginada manualmente.

## Excepciones

|| Excepción | HTTP | Uso ||
||-----------|------|-----||
|| BookNotFoundException | 404 | Libro no encontrado ||
|| BookConflictException | 409 | Conflicto al guardar libro (duplicado) ||
|| GameNotFoundException | 404 | Juego no encontrado ||
|| BoardGameNotFoundException | 404 | Juego de mesa no encontrado ||
|| MagicCardNotFoundException | 404 | Carta Magic no encontrada ||
|| DeckNotFoundException | 404 | Mazo no encontrado ||
|| MovieShowNotFoundException | 404 | Película/serie no encontrada ||
|| MovieShowConflictException | 409 | Conflicto al guardar película/serie (duplicado) ||
|| CatboxUploadException | 502 | Error al subir imagen a Catbox ||
|| UserAlreadyExistsException | 409 | El username ya está registrado ||
|| EmailAlreadyExistsException | 409 | El email ya está registrado ||
|| UserNotFoundException | 404 | Usuario no encontrado ||
|| ForbiddenException | 403 | Operación no permitida (ownership) ||
|| UnauthenticatedException | 401 | Token inválido o expirado ||
|| ForbiddenException | 403 | Acceso denegado a recurso ajeno ||

Todas las excepciones son manejadas por `GlobalExceptionHandler` que devuelve un `ErrorResponse` con timestamp, status, error, message y path.
