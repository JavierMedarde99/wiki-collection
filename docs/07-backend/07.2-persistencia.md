# Persistencia

## Spring Data MongoDB

Se usa Spring Data MongoDB para la capa de persistencia.

### Mappers

Cada entidad tiene su mapper bidireccional (Domain ↔ Entity):

```java
public class BookEntityMapper {
    public Book toDomain(BookEntity entity) { ... }
    public BookEntity toEntity(Book domain) { ... }
}
```

**Patrón:** Todos los mappers siguen el mismo patrón. Los mappers de DTOs (en `adapter/in/web/dto/`) son separados y convierten entre Entity/Domain y DTOs de request/response.

### Configuración MongoDB

```properties
# application.properties
spring.mongodb.uri=mongodb://user:***@127.0.0.1:27017/?authSource=admin&directConnection=true
spring.mongodb.database=collection
spring.data.mongodb.auto-index-creation=false
```

**Nota:** La propiedad correcta es `spring.mongodb.uri` (no `spring.data.mongodb.uri`).

### Auditoría

```java
@Configuration
@EnableMongoAuditing
public class MongoAuditConfig {
}
```

**⚠️ Importante:** Solo hay una clase con `@EnableMongoAuditing`. No añadir otra en el main o en otra configuración porque causa `BeanDefinitionOverrideException`.

### Colecciones MongoDB (9 colecciones)

- **books** — Libros del usuario
- **games** — Videojuegos del usuario
- **board_games** — Juegos de mesa del usuario
- **magic_cards** — Cartas Magic del usuario
- **decks** — Mazos Commander del usuario (con DeckCardEntity embebido)
- **movie_shows** — Películas/series del usuario
- **users** — Usuarios registrados (auth)
- **user_preferences** — Preferencias de colección por usuario
- **user_owned** — Cache de información de ownership (username, displayName)

### Búsquedas con MongoTemplate

Las búsquedas se hacen con `MongoTemplate` + `Query` en lugar de derivar nombres de método de Spring Data. Esto permite:
- Búsqueda case-insensitive con regex
- Filtros dinámicos (solo se añaden criterios si tienen valor)
- Paginación con `Pageable`
- Filtro de visibilidad por ownerId

### Migraciones

|| Migración | Cuando | Qué hace ||
||-----------|--------|-----------||
|| `BoardGameStatusMigration` | Al arrancar | Migra juegos de mesa con estado legacy (PREVIOUSLY_OWNED, FOR_TRADE) a null/OWNED. ejecutado una sola vez ||
|| `UserOwnedBackfillMigration` | Al arrancar | Población de user_owned a partir de usuarios existentes. Evita joins en consultas de ownership ||
|| `UserPreferencesMigration` | Al registrar usuario | Crea UserPreferences con todas las colecciones activas y públicas por defecto ||

### Fase 9: Colecciones Personales

#### UserPreferencesEntity

```java
@Document(collection = "user_preferences")
public class UserPreferencesEntity {
    @Id
    private String id;
    
    @Indexed(unique = true)
    private String userId;
    
    private Map<String, Boolean> activeCollections;  // books, games, boardgames, magic, decks, movieshows
    private Map<String, String> collectionVisibility; // PUBLIC o PRIVATE
    
    @CreatedDate
    private LocalDateTime createdAt;
    
    @LastModifiedDate
    private LocalDateTime updatedAt;
}
```

#### UserOwnedEntity

```java
@Document(collection = "user_owned")
public class UserOwnedEntity {
    @Id
    private String id;
    
    @Indexed
    private String userId;
    
    private String username;
    private String displayName;
}
```

**Propósito:** Evitar joins en consultas de visibilidad. Cuando se consultan elementos de otros usuarios, se joinea con user_owned en lugar de con users.

#### UserEntity

```java
@Document(collection = "users")
public class UserEntity {
    @Id
    private String id;
    
    @Indexed(unique = true)
    @Size(min = 3, max = 20)
    @Pattern(regexp = "^[a-zA-Z0-9_]+$")
    private String username;
    
    @Indexed(unique = true)
    @Email
    private String email;
    
    @JsonIgnore
    private String password;
    
    private String displayName;
    private String avatarUrl;
    
    @Size(max = 200)
    private String bio;
    
    @CreatedDate
    private LocalDateTime createdAt;
    
    @LastModifiedDate
    private LocalDateTime updatedAt;
}
```
