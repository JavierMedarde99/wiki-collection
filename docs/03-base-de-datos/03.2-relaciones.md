# Relaciones

## Modelo Documental

Al usar MongoDB (NoSQL), las relaciones se manejan de forma diferente a SQL. Cada entidad es un documento independiente sin joins nativos.

## Relaciones Existentes

### Books → External Source
- `externalId` referencia un libro en Google Books API
- No hay `externalSource` en el modelo Book (solo se usa externalId)
- No hay integridad referencial; si se borra el libro externo, el local sigue existiendo

### Games → External Source
- `externalId` referencia un juego en RAWG/FreeToGame
- `externalSource` indica la fuente (RAWG, FreeToGame)
- Mismo comportamiento que books

### Board Games → External Source
- `bggId` referencia un juego en BoardGameGeek
- No hay `externalSource` en el modelo BoardGame

### Magic Cards → External Source
- `scryfallId` referencia una carta en Scryfall API
- `oracleId` referencia el oracle ID de Scryfall (único por carta)
- No hay `externalSource` en el modelo MagicCard

## Futuras Relaciones

### Users → Collections (Fase Auth)
```
User (1) ──── (N) Book
User (1) ──── (N) Game
User (1) ──── (N) BoardGame
User (1) ──── (N) MagicCard
User (1) ──── (N) MovieShow
```

Cuando se implemente autenticación:
- Cada documento incluirá un campo `userId`
- Los queries filtrarán por `userId` automáticamente
- Índice compuesto: `{ userId: 1, state: 1 }`

## Patrón de Referencia

Para APIs externas, se guarda solo el ID y la fuente:

```json
{
  "externalId": "XmG1zgEACAAJ",
  "externalSource": "google_books"
}
```

Esto permite:
- Re-consultar datos actualizados si es necesario
- Evitar duplicados (único por externalId + externalSource)
- Mantener la colección local independiente
