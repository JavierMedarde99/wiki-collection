# Arquitectura Backend

## Arquitectura Hexagonal

El backend sigue el patrón de puertos y adaptadores para mantener el dominio aislado de frameworks y tecnologías externas.

### Estructura de Paquetes

```
com.wikicollection/
├── domain/                    # Núcleo del negocio
│   ├── model/                 # Entidades y value objects
│   └── port/
│       ├── in/                # Casos de uso (puertos de entrada)
│       └── out/               # Puertos de salida (repositorios, clientes externos)
├── application/               # Capa de aplicación
│   └── service/               # Implementación de casos de uso
└── infrastructure/            # Capa de infraestructura
    ├── adapter/
    │   ├── in/web/            # Controladores REST
    │   │   └── dto/           # DTOs de request/response
    │   └── out/
    │       ├── persistence/   # Adaptadores de base de datos
    │       └── freetogame/    # Cliente FreeToGame
    │       └── google/        # Cliente Google Books
    └── config/                # Configuración de Spring
```

### Flujo de una Petición

1. **Controller** recibe HTTP request y la convierte a DTO
2. **Service** (application) procesa la lógica de negocio
3. **Domain** valida reglas de negocio
4. **Persistence Adapter** guarda/consulta en MongoDB
5. **External Client** consulta APIs externas si es necesario
6. La respuesta fluye de vuelta por las mismas capas

### Principios SOLID Aplicados

- **S:** Cada clase tiene una única responsabilidad
- **O:** Abierto para extensión, cerrado para modificación
- **L:** Sustitución de Liskov en adaptadores
- **I:** Interfaces segregadas (puertos pequeños)
- **D:** Inversión de dependencias (dominio no depende de infraestructura)
